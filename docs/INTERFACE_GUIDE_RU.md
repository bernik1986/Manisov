# CrewDeck CRM — полная документация интерфейса и эксплуатации

Документ описывает поведение веб-клиента (`app/frontend`), основные сценарии, роли, связь с API и типовой **развёртывание через Docker**. Предназначен для администраторов, внедрения и разработки.

---

## 1. Вход и сессия

### Страница `/login`

- Поля: логин, пароль; кнопка **Войти**.
- Успех: переход на `/menu` (Dashboard).
- Ошибка: сообщение о неверном логине или пароле.

### JWT и хранение

- Токен и объект пользователя: `localStorage` (`authToken`, `authUser`).
- Истечение токена: редирект на `/login`.
- Обновление токена: эндпоинт `/auth/refresh`; фронт пытается обновить сессию до истечения; при `401` по авторизации — очистка и редирект на вход.

### Базовый URL API

Файл `app/frontend/src/api.js`:

- Если задан `VITE_API_BASE_URL` при сборке — он используется (без завершающего `/`).
- Иначе в браузере: `//<hostname>:8000` (тот же хост, порт **8000**).
- Иначе при SSR/отсутствии `window`: `http://127.0.0.1:8000`.

Для продакшена за фронтом на другом домене/без порта 8000 обычно задают **`VITE_API_BASE_URL`** в `.env` на этапе `npm run build`.

## 2. Роли

- Авторизованный доступ ко всем основным страницам.
- Роль **`admin`**: дополнительно `/logs`, `/users`.
- Роль **`recruiter`**: редактирование данных кандидатов, загрузки, шаблоны (по логике API `require_roles`).
- Роль **`viewer`**: как правило только просмотр (ограничения на стороне API для мутаций).

При недостаточных правах API возвращает `403`; фронт может перенаправить в `/menu`.

---

## 3. Навигация (сайдбар)

Пункты: **Dashboard**, **Seamens Data**, **Templates**, **Notifications**, **Logs** (admin), **Users** (admin). Внизу: имя, роль, **Выйти**.

## 4. Dashboard (`/menu`)

- Сводка: число уведомлений, число кандидатов, активный пользователь по audit log.
- Быстрые кнопки: переход в список кандидатов и в уведомления.

## 5. Seamens Data (`/candidates`)

### 5.1 Создание и загрузка

- **Новая пустая карточка** — `POST /candidates`, затем навигация на `/candidates/:id`.
- **Загрузка анкеты** — `DOC`/`DOCX`/`XLS`/`XLSX`/`PDF`; при дубликате возможно объединение; после успеха — диалог «открыть карточку / остаться».
- **Загрузка CV PDF** — парсинг через backend; затем тот же диалог.

### 5.2 Список и фильтры

- Поиск `q` по фамилии/имени/полному имени (debounce на клиенте).
- **`position`** — канонический список должностей; в таблице и в фильтре используются только поля **первой заявки**: `position_applied_for`, затем `rank_applied_for` (раздел «Заявка / recruitment»). Профиль `current_rank` и стаж `rank_on_vessel` для списка **не** применяются. Подробнее: [`SEAMENS_DATA_FILTERS_RU.md`](SEAMENS_DATA_FILTERS_RU.md).
- **`fleet`** — тип судна только из **последнего контракта** (`sea_services.vessel_type`); см. [`SEAMENS_DATA_FILTERS_RU.md`](SEAMENS_DATA_FILTERS_RU.md).
- Состояние фильтров и страницы хранится в **URL**: `q`, `position`, `fleet`, `page`.

### 5.3 Пагинация

- Серверный эндпоинт `GET /candidates/paged` (`page`, `page_size` по умолчанию 20).
- Элементы `<<`, `<`, номера, `>`, `>>`; подпись «Показано X–Y из Z».

## 6. Карточка кандидата (`/candidates/:id`)

### 6.1 Навигация по разделам (вкладки)

Реализация: `CandidateDetail.jsx`, константа `CANDIDATE_SECTION_NAV_ITEMS`.

- Вкладки **горизонтально** под шапкой карточки; **одновременно открыт один панельный раздел** (`expandedSections` как singleton-set).
- Вкладки включают: **динамические группы профиля** (из `candidateFieldGroups`), **B. Заявка / recruitment**, **Documents**, **Certificates**, **Sea service**, **K. Flag documents**, **Family contacts**.
- Подсказка: «Откройте нужный раздел…» (`candidate-section-nav-hint`).

### 6.2 Sea service — модальное окно

- Вкладка **Sea service** не рендерит таблицу в основной колонке: выставляется `seaServiceModalOpen`, показывается **оверлей почти на весь экран** (`SeaServiceSection.jsx`).
- Закрытие: кнопка, клик по оверлею, **Escape**; при перезагрузке кандидата модалка сбрасывается.
- CRUD записей морского стажа через API `createSeaService` / `updateSeaService` / `deleteSeaService`.

### 6.3 Профиль, документы, сертификаты

- Профиль: редактируемые блоки, сохранение по секциям.
- **Documents** / **Certificates**: таблицы, сканы (upload/replace/delete/download), подсветка сроков.
- **Flag documents** / **Family contacts**: в типичной конфигурации **read-only** таблицы.

### 6.4 Удаление и генерация

- Удаление кандидата с подтверждением; возврат к списку с сохранённым query списка.
- **Сгенерировать документы**: модальное дерево папок + множественный выбор только **`.docx`**, генерация через backend.

### 6.5 Фокус из уведомлений

Параметр `focus` в URL подсвечивает строку документа/сертификата (переход из Notifications).

## 7. Templates (`/templates`)

Менеджер папок и файлов (`TemplatesPage.jsx`): дерево, загрузка, rename, delete, drag-and-drop.

## 8. Notifications (`/notifications`)

Группировка по кандидатам и категориям; переход в карточку; для «нет скана» — переход с `focus` на строку.

## 9. Users (`/users`, admin)

CRUD пользователей, роли `admin` / `recruiter` / `viewer`, смена пароля (минимум 6 символов), запрет удаления собственной учётки.

---

## 10. Logs (`/logs`, admin)

Audit log: фильтры по пользователю, датам, быстрые периоды (1/3/7/14/30 дней).

## 11. Типовые сценарии

**A.** Загрузить анкету или CV → подтвердить открытие карточки → дополнить данные.

**B.** Настроить фильтры и страницу в URL → открыть карточку → **Назад** — состояние списка сохраняется.

**C.** В карточке открыть **Sea service** → работа в полноэкранном окне → закрыть по Escape.

**D.** Сгенерировать пакет **DOCX** из выбранных шаблонов.

## 12. Развёртывание (Docker)

### Стек `docker-compose.yml`

| Сервис    | Контейнер          | Порт  | Назначение        |
|-----------|--------------------|-------|-------------------|
| `db`      | `maritime-db`      | 5432  | PostgreSQL        |
| `backend` | `maritime-backend` | 8000  | FastAPI + Alembic |
| `frontend`| `maritime-frontend`| 5173  | Vite dev-сервер   |

Тома backend (из compose): `./uploads`, `./generated`, `./templates` — **код приложения в образе**, после `git pull` нужен **`docker compose build backend`** (или `up -d --build`).

### Команда в образе backend

`Dockerfile`: `alembic upgrade head && uvicorn app.main:app --host 0.0.0.0 --port 8000`

Каталог миграций Alembic задаётся в `alembic.ini` (`script_location` → папка **`migrations/`**).

### Дополнительно: миграции при старте приложения

В `models/db.py` при старте для **не-SQLite** `DATABASE_URL` вызывается **`alembic upgrade head`** (с блокировкой `fcntl` на Linux при нескольких воркерах). Отключение: переменная окружения **`AUTO_ALEMBIC_ON_STARTUP=0`**.

### Деплой с VPS (`deploy.sh`)

Синхронизация `git` в `/var/www/CV-for-seafarers` и **`docker compose up -d --build --remove-orphans`**. Подробнее: `docs/DEPLOY.md`.

### Диагностика ошибок API

В `app/main.py` при необработанном исключении в ответ уходит общий `detail`. Для временной диагностики на сервере: **`CREWDECK_EXPOSE_ERROR_DETAIL=1`** — в JSON добавится поле **`error`** (отключить после отладки).

## 13. Частые проблемы

| Симптом | Что проверить |
|---------|----------------|
| Список кандидатов не грузится | Backend на `:8000`, `GET /candidates/paged`, логи контейнера `maritime-backend` |
| Неожиданный `/login` | TTL JWT, `/auth/refresh`, время на сервере |
| Нет Users/Logs | Роль не `admin` |
| В генерации нет файла | В списке только `.docx` |
| Фронт «бьёт» не в тот API | Пересборка фронта с `VITE_API_BASE_URL` |

Проверка с сервера: `curl -sS -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8000/docs` → ожидается **200**.

## 14. Сопровождение документации

При изменениях обновляйте этот файл и пользовательскую версию `INTERFACE_GUIDE_USER_RU.md`, затем пересоберите Word:

```bash
python scripts/build_docs_docx.py
```

- Auth: `AuthContext.jsx`
